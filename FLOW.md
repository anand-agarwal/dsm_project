# Bachpan — Control flow

This document traces **who calls whom**, from browser bootstrap through every product screen, then through the offline Python pipeline (scrape → indexes → analysis → SQL). Companion: [ARCHITECTURE.md](./ARCHITECTURE.md).

Convention: `A → B` means A invokes B. Local (non-exported) functions are listed under their file.

This file is the **call graph**. For vocabulary (SPA, React, HTTP, ETL), read [ARCHITECTURE.md §0](./ARCHITECTURE.md). Below is a shorter “what is actually happening on the machine” note before each graph.

---

## How to read a call graph (if you are new)

When the atlas runs, there is no separate “server function” for `cmprValue`. A **call** is: JavaScript is executing function A, A’s body names B, the engine jumps to B, B returns, A continues. The stack is just a list of those pauses.

**Render** is a special kind of call: React calls your component function to find out what the screen should look like. Event handlers (`onClick`) are *not* renders; they run later, usually call `setState`, and *then* React renders again.

**Async** (`async function run` in Explore) means: start a network request, give the UI thread back, continue when the JSON arrives. That is why the page can show “Loading…” — `run` is paused at `await supabase.from(...)` while the HTTP round-trip happens.

**Python scripts** are a different process. They do not sit in the React call stack. You start them in a terminal; they read/write files; they exit.

## 0. Two runtime graphs (keep these separate)

```
GRAPH A — Atlas / About / Blog / State dossier
  Browser only. No HTTP to this repo’s backend.
  Data: cmprDataset.ts (map) or mock.ts (dossier).

GRAPH C — Offline pipeline
  Operator runs Python. Writes CSVs / SQL / figures.
  Does not run when a user opens the site.
```

**Why three graphs.** A visitor’s laptop only ever runs A or B. C is how the team *prepares* the numbers those graphs display. Mixing them in your head (“does clicking the map run pandas?”) is the usual confusion; it does not.

## 1. Application bootstrap

```
browser loads frontend/index.html
  → <script type="module" src="/src/main.tsx">
       → createRoot(#app)
       → getRouter()                         [router.tsx]
            → createRouter({ routeTree })    [routeTree.gen.ts]
       → <RouterProvider router>
            → Root route component           [routes/__root.tsx]
                 → HeadContent (meta, fonts, styles.css)
                 → <Outlet />  (matched child route)
```

`getRouter` also registers `DefaultErrorComponent`. That component calls `useRouter()` → `router.invalidate()` on “Try again”.

`routeTree.gen.ts` is generated by `@tanstack/router-plugin` at Vite startup. It wires:

```
__root
  ├── /                IndexRoute      routes/index.tsx
  ├── /about           AboutRoute      routes/about.tsx
  ├── /blog            BlogRoute       routes/blog.tsx
  ├── /explore         ExploreRoute    routes/explore.tsx
  └── /state/$slug     StateSlugRoute  routes/state.$slug.tsx
```

Vite plugins (build time, not request time): `TanStackRouterVite` → `react` → `tailwindcss` → `tsconfigPaths`.

**What the browser is doing here.** `index.html` is dumb: one empty div. `main.tsx` is the true entry. `createRoot` tells React “this DOM node is yours.” `RouterProvider` subscribes to the URL. Root route injects CSS/fonts via `HeadContent` (it writes `<link>` / `<meta>` into `document.head` — still JS, not a second HTML navigation). `<Outlet />` is an empty slot that becomes Atlas or Explore depending on the path.

**StrictMode** (in `main.tsx`) double-invokes some functions in development on purpose, to catch side effects. If you see Explore fetch twice locally, that can be StrictMode, not a bug in `useEffect` cleanup (which *does* set `cancelled = true` to ignore the stale response).

### Mount

```

  → buildIndexKey(indexGroup, gender)             [cmprIndexes.ts]
```

### `computeNationalAverage(year, age, indexKey)`

```
geojson.features
  → NAME_1 | st_nm | name
  → canonicalStateName                            [states.ts]
  → unique set of names
  → for each: cmprValue(stateName, year, age, indexKey)   [cmprIndexes.ts]
  → arithmetic mean, 1 decimal; 0 if empty
```

### `buildIndexKey(group, gender)`

```
if group === "sc" → "CMPR_SC_{gender}"
if group === "st" → "CMPR_ST_{gender}"
else              → "CMPR_{group}_{gender}"
```

### `cmprValue(stateName, year, age, indexKey)`

```
canonicalStateName(stateName)
  → CMPR_DATA_BY_YEAR[year][state][age][indexKey]
  → number | null
```

Does not call `mock.ts`.

**Unidirectional data flow (Atlas).** State lives in `AtlasPage`. Children do not fetch. Toggles call `setYear` / `setGender` / … which re-render the page. Derived values (`selectedIndexKey`, national averages) are computed *during* render from that state. This is the React default: **state down, events up**. There is no Redux store; four `useState` hooks are enough.

**Why national average is computed from GeoJSON names, not from `STATES`.** The map can only color features it has. Averaging the same name set keeps the KPI aligned with visible polygons (after aliases). It is an unweighted mean of state rates, **not** a population-weighted India figure — a statistical choice, not a UI accident.

### `stateDigest(state, year)`

```

cmpr({ ... age: "18-21", female ... })            // returned as cmprFOlder, unused in KPIs

```

### Core model (`mock.ts`)

```
cmpr(opts)
  → cmprBase(state)
       → BASE_CMPR_F_14_17_2011[state] ?? 9 + jitter(...)
  → age multiplier, gender multiplier, year multiplier, category multiplier
  → jitter(seed)
  → clamp → 1 decimal

literacy(state, year, gender)
  → BASE_LITERACY_F_2011[state] ?? 65 + jitter
  → male/year adjustments → clamp

dropoutRate(state, year, gender)
  → cmpr(... 14-17 total)
  → literacy(...)
  → linear combo + jitter

childLabour(state, year)
  → cmpr(... female, 10-13, total)
  → scale + jitter; 2001 × 1.4

educationDist(state, year)
  → literacy(state, year, "female")
  → split literate share with rand()
  → returns named percents

cmprByWorker(state, year, gender)
  → cmpr(... 14-17, category total)
  → multiply by worker-category coefficients
  → jitter per worker

schoolingSplit(state, year, gender)
  → dropoutRate(...)
  → childLabour(...)
  → four buckets summing near 100

generateRawTable(...)     // NOT called by Explore anymore
  → nested loops STATES × ages × genders
  → cmpr + literacy + hash for fake population

nationalAverage(...)      // NOT called by Atlas anymore
  → STATES.map(cmpr | literacy | dropoutRate) → mean

hash / rand / jitter / clamp / cmprBase
  → internal; only used inside mock.ts
```

**This is a generative model, not a lookup.** Each `cmpr({...})` call recomputes from anchors + multipliers. Calling it 36 times in a scatterplot is fine (cheap arithmetic). There is no caching besides React `useMemo` on `stateDigest`. If you replaced this with `cmprValue`, the *call graph* would point at `cmprDataset.ts` instead of `cmprBase`.

**Section E’s worker-attendance chart** invents “Attending” from `100 - workerCMPR - 5`. That is visualization glue, not C-12. When you read FLOW arrows, remember: **a function call does not mean the data is empirical.**

## 5. Route `/explore` — raw tables (Graph B)

### Mount

```
ExplorePage
  useState: tableId, year, area, gender, age, page, allRows, loading, error
  useEffect([tableId, year, area]) → async run()
```

### Fetch (`run`)

```
TABLE_MAP[tableId] → postgres name  (e.g. C-02 → raw_c_02)
if missing → setError, return

hasSupabaseEnv / supabase                         [lib/supabase.ts]
  isValidHttpUrl(VITE_SUPABASE_URL)
  createClient(url, anonKey)  // once at module load
if !supabase → setError (missing env), return

supabase.from(tableName)
  .select("*")
  .eq("year", year)
  .eq("total_rural_urban", area)
  .limit(10000)
  → PostgREST GET
  → Postgres Seq/Index scan on raw_c_*
  → JSON rows → setAllRows
```

Cleanup: `cancelled` flag on unmount / dependency change.

`gender` and `age` are **not** in the effect deps. Changing them does not refetch.

**Why `cancelled`?** `useEffect` starts an async request. If the user changes year before it finishes, two responses can return. The late one must not `setAllRows` for the *old* year. The cleanup function runs when deps change; it sets `cancelled = true` in that closure. This is the standard React fetch race, not specific to Supabase.

**What the network round-trip is.** `supabase.from(...).select()` does not talk SQL from the browser. It builds a URL, `fetch`es it, parses JSON, and returns `{ data, error }`. `setAllRows` stores that array in React state, which triggers a render, which builds `<td>` cells. Loading flags exist because the function is `async`: between click and JSON, the UI still needs something to show.

**Why gender is not in the effect.** Refetching on every gender toggle would re-download the same 10k rows. The extra filters are a **view** on already-fetched data (`useMemo`). Pagination `slice` is even cheaper (array window).

**Download CSV.** `Blob` is an in-memory file. `URL.createObjectURL` makes a temporary `blob:` URL. A fake `<a download>` click uses the browser’s save dialog. No export API exists on the server.

### Client filter (`useMemo`)

```
detectColumn(cols, [/^sex$/i, /gender/i, /male/i, /female/i])
detectColumn(cols, [/^age/i, /age_group/i])
filter allRows by substring match
```

If no matching column exists (typical for C-02-style wide tables), the filter keeps all rows.

### Pagination / export

```
slice = rows[page * 20 : (page+1)*20]
downloadCsv:
  JSON.stringify cells → Blob text/csv → <a download>
```

`C_TABLES`, `YEARS`, `GENDERS`, `AGE_GROUPS` are imported from `mock.ts` as **labels only**. `generateRawTable` is not used.

### `lib/supabase.ts` module init

```
read import.meta.env.VITE_SUPABASE_URL
read import.meta.env.VITE_SUPABASE_ANON_KEY
trim, strip trailing slashes
isValidHttpUrl → createClient | null
export hasSupabaseEnv
```

No other file imports this module.

## 10. Offline pipeline — index builder

All builders import `utils.py`. **Change `DATA_ROOT` / `OUTPUT_DIR` there before running.**

### `run_all.py`

```
if __name__ == "__main__":
  cli_targets = sys.argv[1:] or None
  main(targets)
    validate against TARGETS
    for name in targets:
      _run_target(name)
        TARGETS[name] = (build_fn, stem)
        df = build_fn()                 // one of the four build_df_*
        gender_split(df, f"df_{stem}")  [utils.py]
        return { df_{stem}_state.csv, _male.csv, _female.csv }
    save_outputs(all_outputs)           [utils.py]
```

`TARGETS`: `total` → `build_df_total`, `SC` → `build_df_SC`, `ST` → `build_df_ST`, `religion` → `build_df_religion`.

**Orchestrator pattern.** `run_all` does not know how C-04 works. It only knows a dictionary of `name → function`. That is the same idea as the frontend router: a table of names to handlers. Each `build_*` is a **pipeline stage** with a uniform output shape (`GEO_KEYS` + metrics) so `_outer_merge` can join like SQL `FULL OUTER JOIN` on state×bracket.

**Why parse functions are duplicated (SC vs ST).** Copy-paste keeps each file readable in isolation (same column maps). The downside is bug fixes must be applied twice. A more “software engineered” version would pass `PREFIX` and dataset keys into one module — which `build_ST` already almost is.

Each `build_*.py` also has its own `main()` for a single-target run that calls the same `build_df_*` → `gender_split` → `save_outputs`.

Excel I/O:

```

  → _detect_engine (PK zip vs OLE)

```

Names / geography:

```

  → _normalise_raw

_make_geo(state_code, state_name, bracket) → dict of GEO_KEYS

_state_slice(df)
  → area_type == Total
  → 2001: district_code == '00' and tehsil_code == '0000'
  → 2011: district_code == '000'
```

Brackets:

```

  → _normalise_age_label on labels and cells
  → boolean mask

  → _rows_for_bracket

```

Math / assemble / write:

```

save_outputs({filename: df})
  → _reorder_geo_first
  → to_csv(OUTPUT_DIR)
```

```
  write supabase/migrations/20260426165000_create_raw_census_tables.sql
```

### `generate_raw_census_seed_migration.py`

```
main()
  same grouping as migration generator
  read_rows(csv)
  sql_literal(value)
  emit BEGIN; INSERT ...; COMMIT
  write 20260426170000_seed_raw_census_data.sql
```

Apply with Supabase CLI / SQL editor. Explore then reads those rows (Graph B). Compiling `cmprDataset.ts` from `output_datasets_*` is a **manual** step not encoded as a script.

**Code generating code.** These scripts treat CSV headers as a schema. That is **metaprogramming**: Python writes SQL that Postgres later executes. The risk is header typos becoming column names (`females_4`). The benefit is not hand-writing 24 `CREATE TABLE`s. The missing piece in-repo is TS generation for `cmprDataset.ts` — that last mile is still human, which is why atlas and CSVs can drift.

## 13. End-to-end user journeys

### Journey 1 — “Show me female 14–17 total CMPR on the map”

```
User opens /
  AtlasPage defaults: year=2011, gender=female, age=14-17, index=total
  buildIndexKey("total","female") → CMPR_total_female
  IndiaMap paints each state via cmprValue → cmprColor
  computeNationalAverage uses the same key
User changes Index dropdown → buildIndexKey → IndiaMap re-renders (no network)
User clicks Odisha
  stateSlug("Odisha") → "odisha"
  navigate /state/odisha
  loader: stateFromSlug → { name: "Odisha", ... }
  StatePage: stateDigest / charts from mock.ts (not cmprDataset)
```

Clicking a state is **client-side navigation**: the JS router updates the URL and mounts another component. The map’s SVG is destroyed (unmounted) and the dossier mounts. The CMPR number you just hovered is *not* passed as a prop; the dossier recomputes from `mock.ts`. That is why the KPI can disagree with the map — different graphs, not a bug in `navigate`.

## 15. Failure paths

```
#app missing → main.tsx throws "App container not found."

Unknown URL → __root NotFoundComponent

Unknown state slug → state route notFoundComponent

Supabase env invalid → explore error string, empty table

PostgREST error → explore setError(message | details | hint)

cmprDataset miss (state/age/key) → cmprValue null → map fill muted, tooltip "NA"

Index builder missing Excel → _glob_files warning, empty frame, save_outputs SKIPPED

safe_div by zero / NaN → np.nan in CSV (atlas compile must decide null)

NADA download fail → download_file retries then counts failed; continues loop
```

`DefaultErrorComponent` catches render/loader exceptions: `router.invalidate()` + `reset()`, or `<a href="/">`.
